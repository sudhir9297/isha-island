# Traveler luggage

Four Blender-authored props based on `luggage-turnarounds.png`: terracotta suitcase, sage backpack, ochre duffel and indigo crossbody satchel. The reference sheet was made with the built-in image generator; the meshes were authored directly in Blender (not generated by Meshy).

`traveler-luggage.blend` contains the character fitting scene, with each bag constrained to its carrying bone. `../../public/models/traveler-luggage.glb` is the centered, unparented game export with four named objects. `../../scripts/build_luggage.py` builds the geometry and exports the GLB. The fitting scene adds attachment constraints after export; game attachment and release are controlled by `Journey.jsx`.

Palette: terracotta leather, sage canvas, ochre canvas, indigo canvas, walnut trim, brass hardware. Details include piping, stitches, pockets, buckles, carry handles, suitcase wheels and satchel strap. Materials are simple portable PBR colors/roughness; the illustration's fabric grain is not baked into a texture.

The game loads these through `TravelerModels.jsx`, clones each prop independently, and preserves boat stowage and baggage-release animation. Backpack and satchel offsets were adjusted to clear the Meshy character's body. Asset bounds and release trajectory tests pass; visually checked in Blender and the running game.

Carry-fit update: `LuggageCarry.js` aligns suitcase and duffel handle centers with the hand bones and turns the long duffel fore/aft to clear the dhoti. The carrying pose opens the arms slightly; backpack and satchel follow the torso with clearance. The duffel handles converge at a shared grip. The satchel exports separate loose and torso-fitted straps, switched for carried versus stowed/released states. Run `fit_luggage_preview.py` after `build_luggage.py` to restore the fitted Blender working scene. The preview has the carrying pose; exported character animation remains unchanged.

Regression checks sample 24 walking frames at four headings, including transformed bag parents, to check hand/handle alignment, side clearance and floor clearance. These checks cover attachment positions, not full triangle-level collision detection or individual finger articulation.

Hand-grip refinement: the character now includes a `CarryGrip` morph, authored by `scripts/refine_traveler_grip.py`. It curls the existing mitten-style fingers inward and tucks the thumb slightly, without changing the relaxed base mesh. `updateTravelerGrip` blends it in while carrying and out when seated/released. The handle anchors were moved into the curled palms. The morph is in `traveler-luggage.blend` and the exported character GLB; the pre-grip GLB is backed up under `assets/characters/versions/pre-grip`. To export from the fitted working scene, run `export_traveler_grip.py`, then `finalize-traveler-walk.mjs`, then restore the preview with `fit_luggage_preview.py`. The added test checks localization to the hands and reversible grip blending.

Face update: `refine_traveler_face.py` closes the mouth under the moustache, smooths the old eyelids and adds two head-parented oval eyes with `Blink` morphs. `TravelerFace.js` drives eased blinking in both the game and showroom. The showroom's Inspect face button provides a close-up. The working Blender scene contains the face source shape and the edited face; the pre-edit game model is backed up in `assets/characters/versions/pre-face`. Re-export includes the two eye meshes and their morphs. The new face test checks that both eyes close/reopen together and remain attached to the head.

Run/Jump update: the latest editable Blender file is `../characters/sankaran-animated.blend`, left on the Run action. Both the rig and garment have paired Run and Jump NLA tracks. Run is a 16-frame cycle at 24 fps; Jump is a 36-frame one-shot with anticipation, root lift, landing compression and recovery. `scripts/create_traveler_run_jump.py` authors the clips; the GLB includes Idle, Walk, Run, Jump, Seated and Point. Run/Jump cloth samples are in `../characters/run-jump-samples.json` and applied by `finalize-traveler-walk.mjs` after Blender export. The showroom animation selector previews these clips; Replay jump restarts the one-shot. These are animation assets/previews, not new player input or jump physics.

Eye seating: `scripts/fit_traveler_eyes.py` ray-projects both the open-eye and blink geometry onto the face, with a shallow 1–5 mm front relief and embedded back surface. Run it in the neutral pose after face creation and before baking/exporting motions. An exported-model raycast test checks the eye/skin gap in both states. The pre-update model is backed up in `../characters/versions/pre-run-jump`.

Playable-map integration: hold Shift with WASD/arrows to run at 1.75× the current walking speed; Space triggers one Jump on land and remains the boat brake aboard. Touch controls expose Run and Jump on land. `TravelerMotion.js` samples the exported Blender Run/Jump clips after the procedural gait and restores their bindings before each new pose, preventing lingering jump/root offsets. Jump uses the 1.5-second authored vertical root motion, while horizontal movement retains shoreline, wall, seat and boat collision checks. Resting/boarding are blocked during the jump; pause freezes its clock. Short Space/touch taps are queued until the simulation consumes them. Tests cover speed, one jump per press, pause/reset, wall/boat restrictions and motion cleanup.
